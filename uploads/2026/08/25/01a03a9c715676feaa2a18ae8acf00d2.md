# Full-Stack Interview Glossary (C#/.NET + React/TypeScript)

Target vocabulary for a mid-level full-stack interview. Definitions here become the canonical wording used across all lessons — and good interview answers. (Seeded as a target list; promote a term from "to-master" to confirmed only once you can define it from memory.)

## C# & .NET

**Deferred execution**:
A LINQ query isn't evaluated until enumerated; the query is a recipe, not a result.
_Avoid_: lazy loading (overloaded term — that's EF navigation loading).

**Value type vs reference type**:
Value types copy on assignment and live where declared; reference types hold a reference to heap data. Boxing wraps a value type in a heap object.
_Avoid_: "stack vs heap" as the definition (implementation detail, not the contract).

**`IEnumerable` vs `IQueryable`**:
`IEnumerable` evaluates in memory; `IQueryable` translates expressions (e.g. to SQL) so filtering happens at the source.
_Avoid_: "IQueryable is just LINQ."

**`Task` vs `ValueTask`**:
`Task` is the unit of async work (heap-allocated, often cached for hot paths); `ValueTask` avoids allocation when an async op frequently completes synchronously.
_Avoid_: "ValueTask is faster" without the synchronously-completes caveat.

**Captive dependency**:
A longer-lived service (e.g. Singleton) holding a shorter-lived one (e.g. Scoped), keeping the short one alive past its intended lifetime.
_Avoid_: "DI cycle."

**Change tracking**:
EF Core's DbContext records entity state (Added/Modified/Deleted/Unchanged) so `SaveChanges` issues the right SQL.
_Avoid_: "EF caching."

## TypeScript

**Structural typing**:
A type matches if it has the required shape, regardless of name — "if it walks like a duck."
_Avoid_: "duck typing" (that's runtime; this is compile-time).

**Narrowing**:
Using control-flow (`typeof`, `in`, truthiness, type guards) to refine a broad type to a narrower one within a branch.
_Avoid_: "casting" (assertion forces a type; narrowing proves it).

**Discriminated union**:
A union of object shapes sharing a literal-typed discriminator field, enabling exhaustive narrowing.
_Avoid_: "enum union" (enums aren't required and are often worse here).

**`unknown` vs `any`**:
`unknown` is type-safe: you must narrow before use. `any` opts out of checking entirely.
_Avoid_: using `any` as "I don't know the type" — that's `unknown`.

## React

**Render**:
React calling a component function to produce its element tree. Re-render = running it again when inputs/state change. Not the same as DOM update.
_Avoid_: "paint," "reflow" (those are browser/DOM terms).

**Reconciliation**:
React diffing the new tree against the previous to decide the minimal DOM change. Keys identify which children persist.
_Avoid_: "virtual DOM diffing" as if it's the whole story.

**Effect**:
`useEffect` runs side effects after render/commit, re-running when deps change, with optional cleanup before the next run.
_Avoid_: "lifecycle method" (class-era term).

**Memoization**:
Caching a value/element so an unchanged input doesn't recompute — `useMemo`, `useCallback`, `React.memo`. Often wasted if the inputs change every render anyway.
_Avoid_: "optimization" without naming the memo used.
